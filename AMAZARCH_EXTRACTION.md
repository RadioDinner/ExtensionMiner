own repository before store submission (see `amazarch/SPEC.md`: *"Lives in this
repo for now; can be extracted to its own repo before store submission."*). AMO
(Firefox) reviews your source, so a clean, standalone repo makes that painless.

## Do the move (once)

```bash
# 1. Create an EMPTY private repo named "amazarch" on GitHub — do NOT add a
#    README/.gitignore/license (we're pushing history):
#      https://github.com/new  →  owner: RadioDinner, name: amazarch, Private

# 2. Clone from the bundle I sent you (preserves full history):
git clone amazarch.bundle amazarch
cd amazarch
git remote remove origin

# 3. Point at the new repo and push:
git remote add origin https://github.com/RadioDinner/amazarch.git
git branch -M main
git push -u origin main

# 4. Sanity-check the standalone repo:
npm install && npm test && npm run build
```

(No bundle handy? The `amazarch/` folder in this repo is byte-identical — you
can also `cp -r amazarch ../amazarch-standalone && cd ../amazarch-standalone &&
git init && git add -A && git commit` — but that loses the commit history the
bundle preserves.)

## After the new repo exists

1. **Keep it private for now.** Flip it public (or upload a source package)
   when you submit to AMO; keep it private through the paid-beta if you prefer.
2. **Let Claude Code work in it:** start a session on the new repo (or
   `add_repo RadioDinner/amazarch` in an existing one) so future Amazarch work
   happens there.
3. **Retire the monorepo copy:** once you confirm the new repo has everything,
   `amazarch/` here can be replaced with a one-line pointer (or deleted). I left
   it in place deliberately so nothing is lost before the new repo is live — say
   the word and I'll remove it and leave a pointer in a follow-up commit.
