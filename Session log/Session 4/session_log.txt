DISCOVERY (get every extension)
  --all-categories : discover the WHOLE category taxonomy from the store's nav
       (parse.extract_category_slugs over the homepage), not 2 hardcoded slugs.
  Exhaust-scroll   : CWSBrowser.collect_scrolling scrolls a category until no new
       ids appear (cap --category-scrolls=40, --discovery-patience=3).
  --follow-related : breadth-first GRAPH crawl — scrape_extension returns the
       detail page's related ext_ids; crawl() runs a frontier queue (seed from
       categories, enqueue related), --max-total caps it. This was the fix for
       "only got 57": the 2 category slugs returned the same default listing.
  --preset daily implies --all-categories + --follow-related + refresh.

REVIEWS (get every available review + signal)
  Multi-sort: fetch_review_sorts re-sorts the reviews page and merges, de-duped
       on dedupe_uid (store id else content hash). Sort control CONFIRMED from
       live DOM: trigger [role=combobox][aria-haspopup=listbox]; options
       li[role=option][title="..."]; titles "Recent" / "Helpful" / "Highest to
       lowest rating" / "Lowest to highest rating".
  "Show more": _expand_reviews clicks every per-review expander (text-matched;
       "Show more" confirmed) before each snapshot -> full bodies (also keeps the
       content-hash id stable across runs).
  "Load more": _load_all_reviews clicks the logged-out reviews "Load more" button
       until gone (--load-more-max=40/sort) -> paginates past the first ~10.
  Helpful flag: reviews appearing under the "Helpful" sort get a STICKY
       reviews.helpful_ranked = true (migration 996). merge_reviews OR-s the flag
       across sorts + de-dupes; persist writes it via a separate monotonic UPDATE
       (db.mark_reviews_helpful) so a later recent-only re-scrape never clears it.
  Recent + daily + upsert dedupe => the stored review set GROWS past 10 over time.
