SCRAPER — CONCURRENCY (open item #4)   commit a69a30e
  scraper/crawl.py — rewrote crawl() from a single-threaded deque loop to a
    thread-safe worker pool:
      * CrawlOptions.concurrency (default 1).
      * build_worker_browser(s, opts, shared_rl): builds a browser per worker and
        injects ONE shared RateLimiter (real browser only; the test fake has no
        .rate_limiter attr so it's left untouched). The on-disk cache is already
        shared by directory, so only the limiter needs sharing.
      * Seed phase (serial, main thread): discover categories + collect ids ->
        enqueue. Running it in the main thread means a broken browser env (no
        Playwright/Chromium) still raises up to main() -> explain_failure, before
        any worker spins up.
      * Process phase: N daemon threads, each its OWN browser (Playwright sync API
        is thread-affine — a browser canNOT be shared across threads). Frontier is
        a queue.Queue; --follow-related pushes new ids back on as workers run;
        completion = frontier.join() + one None sentinel per worker.
      * Thread-safety: discovered/seen/stats each behind a Lock; enqueue() guards
        discovered + max_total atomically; process_one() fully wraps scrape+persist
        so one bad page never kills a worker.
      * Hang guard: if EVERY worker fails to start a browser, the last one drains
        the queue so frontier.join() can't block forever (unreachable in practice
        because the seed phase already validated the browser, but cheap insurance).
    WHY shared limiter + many workers still helps AND stays polite: per-extension
    wall-time is dominated by on-page work (scroll / "Load more" up to 40 clicks /
    "Show more"), NOT navigation. Workers overlap that on-page time; the shared
    limiter paces only goto() so the aggregate request rate is unchanged. Rough
    ceiling at the polite 3s rate is ~nav-bound; concurrency turns a ~24/hr serial
    crawl into ~hundreds/hr.
  scraper/run.py — --concurrency N (default None -> 1 interactive, 4 under
    --preset daily; explicit value wins over the preset). Daily log line now
    reports worker count + "Recent + Helpful". --no-multi-sort help text updated.

* Migrations count DOWN from 999; lowest existing is 996. Next NEW one = 995.
* Concurrency model: each worker = its own Playwright browser (sync API is
  thread-affine — do NOT try to share a browser across threads). Shared state is
  ONLY the RateLimiter (injected) + the dir-based cache; everything mutable is
  lock-guarded. Default concurrency 1 keeps the interactive path + tests
  deterministic; daily preset uses 4.

  UPDATE, kept OUT of Review.to_row(). Requires migration 996 (see open item #1).

  helpful_ranked column hides the section rather than erroring the whole page.
* Egress: the Chrome Web Store is HTTP 403 in the web env — scraper must run on
  the user's machine. PyPI + Anthropic API are reachable here (tests + ranking).
