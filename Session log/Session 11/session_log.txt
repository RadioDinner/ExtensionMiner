PART B — v0.7.0: REFUND MATCHING (prompt 2 — "lets get to refund matching")
================================================================================
The M3 core / headline paid feature. Money-in Monarch rows (credits) now match
back to the Amazon order they refund. SHIPPED:

1. matcher.ts — refund matcher. Rules (SPEC §3 rule 4):
   - FULL: credit == order.totalCents, 0 <= (creditDate - orderDate) <= 120
     (refundWindowDays, configurable). Unique → "auto". Multiple same-amount
     candidates: if EXACTLY ONE carries a returnHint → "auto" on it (hint
     disambiguates, beats date proximity); else "review" (hinted-first, then
     closest date).
   - PARTIAL: credit < a RETURN-HINTED order's total in window → "review",
     NEVER auto. Hint is REQUIRED for partials (totals alone can't evidence a
     partial amount). Full match always preferred over partial.
   - No candidate → status "refund" = unmatched credit (listed, not dropped).
   - MatchResult gained kind:"charge"|"refund" + refundMatch:"full"|"partial";
     summary's `refund` count now means UNMATCHED refunds only.
2. returnHint — scraped from order-card text. RETURN_HINT_RE
   (amazon-order-parse.ts) matches COMPLETED-return phrases only ("Refund
   issued", "Return complete", "Refunded", "Track your refund", "Item
   returned"…) and deliberately NOT the "Return or replace items" / "Return
   eligible through…" text on every delivered card (tested both ways).
   Hint captured in the DOM path (content/amazon) and HTML path
   (parseAmazonOrders); background dedupe merges hint=true onto seen orders.
3. Writes — buildRefundNoteLine ("[Amazarch] Refund — items · #id · link",
   partial variant "Partial refund — …") + buildRefundMerchantName
   ("Amazon refund — <summary>"). Refunds flow through the SAME v0.4.11
   verified-write + undo path and the SAME auto-apply toggles (unique-full
   refunds auto-apply when autoMatch+autoNote/autoRename on; partials never).
4. Plumbing — onApply/onRename signatures changed to take the full
   MatchResult (overlay.ts PanelView, content/monarch/index.ts, auto-apply
   callback). Armed-undo registry keys unchanged (chargeId:note/rename).
5. Overlay — matched refunds show ↩ with status color, "refund of <date>
   order · item (+Nd)" / "partial refund of…"; unmatched: "refund — no order
   matched in the sync window"; summary line says "N refunds unmatched".
6. Tests 116 → 136, all green; typecheck + chrome/firefox builds green.
   Version 0.7.0 (package.json + both manifests). README status updated.
