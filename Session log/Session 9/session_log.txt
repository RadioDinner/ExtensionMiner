THE LONG DEBUG ARC (so next session doesn't re-litigate)
================================================================================
Milestones M0→matcher→writes, then a long reliability grind. Key resolved bugs:
  - Monarch auth: NOT a localStorage bearer token; it's cookie + X-CSRFToken.
    Same-origin request from the content script. (v0.0.x)
  - Read query self-heals: tries [search×name] combos; `name` field is rejected
    by Monarch's read schema, so it drops to a name-less query. (v0.4.1)
  - Amazon orders: raw fetch = ciphertext (Siege CSD). Read rendered DOM via a
    background tab + amazon content script. (v0.0.9)
  - Amazon "0 orders": background-tab decryption timing; MAX_WAIT raised to 40s;
    diagnostic added (cardCount/decrypted/url/waited). (v0.4.3)
  - **THE BIG ONE — sync "stopped working" ("Receiving end does not exist"):**
    Making sync on-demand (v0.3.0) meant fetch-amazon is sent minutes after
    load, by which point Firefox idle-suspended the background EVENT PAGE, and
    it would not wake for the message. Retries (v0.4.5) and a keepalive PORT
    (v0.4.7) were insufficient. FIX = periodic keepalive PING: the content
    script sends get-status every 15s (under Firefox's ~30s idle timeout) to
    keep the background warm the whole time Monarch is open. (v0.4.9) A on-load
    background health check ("Background connected ✓") isolated it. (v0.4.8)
  - Perf: attach the panel to document.documentElement (not <body>) so
    Monarch's React doesn't wipe it and retrigger redraws; sync is on-demand
    (no heavy work on page load). (v0.3.0 + v0.4.0)
  - Vanity timer: an independent 1s heartbeat, decoupled from status labels. (v0.4.6)
